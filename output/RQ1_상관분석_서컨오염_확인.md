# 상관분석(1단계) 코드 확인 결과 — 서컨, 회귀분석과 동일한 문제 있음 (긴급)

`RQ1_스크립트/correlation_analysis.py`와 그 입력 파일(`물동량_downloads/물동량_상관분석용.csv`)을 직접 열어서 확인했습니다. **회귀분석 때와 똑같은 문제가 상관분석에도 그대로 있었습니다.**

## 1. 확인 결과

- `correlation_analysis.py` 코드 상단 주석(18번째 줄)에는 "서컨물동량은 2024-03-09 이후만 사용 (물동량_상관분석용.csv에 이미 반영되어 있음)"이라고 적혀 있습니다. 즉 입력 파일이 이미 개장 전을 제외해 준다고 가정하고 있습니다.
- 하지만 `물동량_상관분석용.csv`를 직접 열어보니, 2024-03-09 이전 798행 중 **795행의 서컨물동량이 NaN이 아니라 정확히 0.0**으로 채워져 있었습니다. 즉 "제외"가 안 돼 있고, 대신 "개장 전엔 실제로 물동량이 없었다"는 뜻의 0이 그대로 들어가 있습니다.
- 이 코드의 상관계수 계산 함수(`correlation_matrix`)는 `pair.dropna()`만 하기 때문에, 0.0은 NaN이 아니라서 걸러지지 않고 **실제 관측값으로 그대로 상관계수 계산에 들어갑니다.**
- 실제로 저장된 `RQ1_상관계수_행렬.csv`를 열어보면, 서컨물동량과의 상관계수는 대부분 N=1,441~1,449로 나와 있습니다. 이는 2022-01-01부터의 전체 기간(개장 전 포함)이 거의 다 쓰였다는 뜻입니다 — 개장 후 유효기간만 쓴다면 N은 650대여야 합니다.
- 즉 **1위로 보고됐던 서컨-남해선(순천-부산) 북부산TG-김해JC 조합(r=-0.5063)뿐 아니라, 서컨물동량이 걸린 상관계수 전체(2위 중앙선 대동IC-초정IC -0.3639, 3위 남해2지선 가락IC-서부산TG +0.3585 등 포함)가 같은 오염의 영향을 받은 수치입니다.** 회귀분석과 마찬가지로, 개장 전(물동량=0)/개장 후(물동량 정상)라는 단절적 구조 자체가 도로 변수와 강하게 연관된 것처럼 보이는 착시를 만들었을 가능성이 큽니다.
- 참고로 북컨·남컨물동량은 이 파일에서 처음부터 정상 값이 들어 있어 문제가 없습니다(개장/폐쇄 이벤트가 없는 물동량이라 원천적으로 해당 없음).

## 2. 왜 회귀분석 때 못 걸렸는지

회귀분석은 팀에서 제공한 "정제 완료" 파일(`RQ1_회귀분석용_서컨물동량.csv`)을 썼고, 상관분석은 그보다 앞단의 원본 물동량 파일(`물동량_상관분석용.csv`)을 썼습니다. 서로 다른 단계에서 각자 "이미 처리되어 있겠지"라고 가정한 게 똑같이 틀렸던 것으로 보입니다. 근본 원인은 같습니다 — **개장일 필터가 최종적으로 쓰이는 파일에 실제로 반영됐는지를 파일명이나 이전 처리 이력만으로 확인하지 않았다는 점.**

## 3. 코드 수정

`correlation_analysis.py`의 `load_cargo_volume()` 함수에서, 원본 CSV를 불러온 직후 서컨물동량 컬럼의 2024-03-09 이전 값을 NaN으로 다시 덮어쓰도록 수정했습니다(회귀분석 코드에서 쓴 것과 동일한 원칙 — 원본을 불러오는 시점에 매번 필터를 다시 적용). 수정한 스크립트를 같이 첨부합니다.

이 스크립트는 로컬 `교통데이터_1차정리`, `VDS_구간별_시간대별` 폴더의 원본 데이터를 읽어야 실행되는데, 이 폴더들은 이번 세션에 올라와 있지 않아 제가 직접 재실행은 못 했습니다. 팀원 컴퓨터(또는 원래 실행 환경)에서 이 수정된 스크립트로 다시 돌려서 `RQ1_상관계수_행렬.csv` / `RQ1_상관계수_행렬_v2_신항선총교통량.csv`를 새로 만들어야 합니다.

## 4. 다음에 할 일

1. 수정된 `correlation_analysis.py`를 원래 환경(팀 컴퓨터, `RQ1_스크립트` 폴더)에서 재실행 → 새 상관계수 행렬 확보.
2. 특히 1위였던 서컨-남해선 북부산TG-김해JC(r=-0.5063) 조합은, 이 구간이 2023-12-04 이후 데이터가 아예 끊긴 죽은 변수라는 점(회귀분석 단계에서 발견)까지 겹쳐 있어 재확인 후 순위에서 빠지거나 크게 낮아질 가능성이 높습니다.
3. 새 상관계수 결과가 나오면, 시차분석(2단계)에서 서컨 관련 lag를 이 오염된 상관계수 기준으로 탐색했었는지도 같이 확인이 필요합니다(이미 앞선 문서에서 지적했던 항목).
4. 팀 상관분석 결과 문서·발표자료에 있는 서컨 관련 수치(특히 "1위 상관 r=-0.5063")는 재실행 전까지 잠정 보류로 표시해 두는 걸 권장합니다.
