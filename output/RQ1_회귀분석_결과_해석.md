# RQ1. 시차 적용 회귀분석 — 결과 해석

`busancargo/lag/`, `busancargo/output/` 폴더에서 실행한 결과를 확인한 내용입니다. **이번 버전은 팀원이 재실행한 시차분석(2단계) 결과를 반영해 lag값·변수 구성을 갱신하고, 상관분석과 같은 v1(화물차환산)/v2(전차종원시) 두 버전을 같이 도는 코드로 다시 돌린 결과입니다. 숫자가 지난 버전과 또 달라졌습니다.**

## 0. 코드 수정 이력

### 0.1 (1차) 다중공선성 통합모델 데이터 소스 버그

"다중공선성 해결(통합변수) 모델"이 원래 모델과 다른 데이터 소스를 쓰고 있어 표본 수가 안 맞았던 문제. 같은 데이터로 비교하도록 수정.

### 0.2 (2차) 윈도우 콘솔/폰트 경고 + 로버스트 표준오차(HC3)

1. 실제로 렌더링 가능한 한글 폰트인지 확인한 뒤에만 설정하도록 수정 — `findfont` 경고 반복 출력 해결.
2. 윈도우 콘솔(cp949) 한글 출력 깨짐 방지 — `sys.stdout.reconfigure(encoding="utf-8")` 추가.
3. 이분산성이 확인된 물동량에 로버스트 표준오차(HC3) 적용 로직 추가.

### 0.3 (3차) Q-Q plot 스케일 버그

`sm.qqplot(resid, line="45")`를 `fit=True` 없이 호출해서, 이론적 분위수 축이 항상 표준정규분포(-3~3)로 고정되고 실제 잔차(수천 단위)와 스케일이 안 맞아 점들이 세로로 눌린 것처럼 보이는 착시가 있었습니다. `fit=True`를 추가해 해결했습니다.

### 0.4 (4차·중요) 서컨 데이터 오염 재확인 — 결과 대폭 수정

임노아님이 카톡에서 "서컨(7부두)은 2024-03-09에 개장했으니 그 이전 기간은 실제로 제외됐어야 한다"고 짚어주신 걸 계기로 회귀분석 파일을 직접 열어 날짜별로 확인했습니다.

- 팀에서 "정제 완료"로 공유된 파일에도 개장 전(2024-03-09 이전) 793행이 걸러지지 않고 남아 있었고, 이 값들이 요일별 평균 계산에 섞여 들어가면서 개장 이후 정상 구간의 편차값까지 함께 왜곡돼 있었습니다.
- 코드를 고쳐서, 서컨물동량은 어떤 파일을 쓰든 상관없이 원본 wide table에서 개장일 필터를 다시 적용하도록 만들었습니다.
- 같은 문제가 상관분석(1단계) 입력 파일에도 있었던 것을 확인해서 그쪽도 고쳤습니다(`RQ1_상관분석_서컨오염_확인.md` 참고). 이 문제로 상관분석 1위였던 서컨-남해선 북부산TG-김해JC(r=-0.5063)가 죽은 변수(2023-12-04 이후 데이터 단절)와의 우연한 조합이었다는 것이 확인되어, 아래 0.5의 재실행에서 이 변수는 후보에서 완전히 빠졌습니다.

### 0.5 (5차·이번) 시차분석(2단계) 재실행 반영 — lag값·버전 구성 갱신

팀원이 오염 제거된 데이터로 상관·시차분석을 다시 돌려서 `busancargo/lag/` 폴더에 새 파일을 넣어줬습니다. 그대로 이전 코드를 재사용하면 안 되는 상태였어서(파일명이 바뀌었고 lag값도 달라짐) 아래처럼 코드를 갱신했습니다.

- **lag값 변경(서컨)**: 남해2지선 가락IC-서부산TG 5→**1**일, 남해선 김해JC-동김해IC 5→**7**일, 신항선 진해IC-남문대교 13→**7**일(신항선 3구간 전부 lag7로 통일).
- **변수 제외(서컨)**: 남해선 북부산TG-김해JC를 후보에서 완전히 뺐습니다(0.4 참고 — 오염 제거 후 상관계수 자체가 안 나오는 죽은 변수로 확인됨).
- **버전 분리**: 상관분석과 마찬가지로 부산신항선 교통량을 v1(화물차환산_통행량)/v2(전차종원시 원시 총교통량) 두 가지로 나눠서 둘 다 산출하도록 코드를 고쳤습니다. 아래 표는 두 버전을 나란히 보여줍니다.
- 재실행 결과, 팀원이 만든 `RQ1_회귀분석_원본단위_요일더미_결과요약.csv`의 수치(서컨 v1 R²=0.1310, v2 R²=0.1499)와 이 코드로 직접 재현한 값이 정확히 일치하는 것을 확인했습니다.

## 1. 결과 요약 — 이번엔 뭐가 달라졌나

- **서컨 R²가 소폭 낮아졌습니다** (버전B 기준 이전 0.1692 → 이번 v1 0.1310 / v2 0.1499). lag가 바뀌고 표본이 373→374로 살짝 늘었는데, 무엇보다 신항선 진해IC-남문대교가 lag13→7이 되면서 다른 두 신항선 구간과 상관이 세져 다중공선성이 더 심해진 영향이 큽니다.
- **VIF가 더 나빠졌습니다.** 신항선 대청IC-진해IC/남진례IC-대청IC는 여전히 최상위권 VIF(v1: 360/531, v2: 148/219)고, 이번엔 **진해IC-남문대교(lag7)도 VIF 58.7(v1)/32.1(v2)로 같이 높아졌습니다** — 예전엔 lag13이라 따로 놀았는데 이제 세 구간이 다 lag7이라 서로 얽혀버린 겁니다. 지금 코드의 다중공선성 통합은 대청IC-진해IC·남진례IC-대청IC 두 개만 묶는데, 통합해도 최대 VIF가 42.5(v1)/24.9(v2)로 **여전히 10을 넘습니다** — 진해IC-남문대교까지 같이 묶든지, 이 구간을 아예 후보에서 빼든지 추가 조치가 필요해 보입니다(9.1 참고).
- **v1과 v2에서 결론이 갈리는 지점이 생겼습니다.** 신항선 통합변수가 v1에서는 p=0.076으로 유의하지 않고, v2에서는 p=0.007로 유의합니다. 즉 "신항선 통행량과 서컨 물동량의 관계"는 화물차 비중을 곱하느냐 안 곱하느냐에 따라 결론이 달라지는, 아직 확정하기 이른 상태입니다.
- **유일하게 두 버전·두 모델(원래/통합) 전부에서 일관되게 유의한 건 남해선 김해JC-동김해IC입니다** (v1 원래모델만 p=0.053으로 경계선, 나머지 세 조합은 p<0.03). 이번 재실행에서 가장 믿을 만한 단일 결과는 이겁니다.
- 북컨·남컨은 이번 재실행과 무관합니다(lag·변수 구성 그대로) — R²도 이전과 거의 같습니다(북컨 0.033~0.035, 남컨 0.035~0.036).

### 9.2 RQ1 → RQ3용 탄력성(elasticity) 변환

신항선 관련 계수는 다중공선성·v1/v2 불일치가 해소되기 전까지 탄력성 변환을 보류하는 걸 권장합니다. 우선 남해선 김해JC-동김해IC부터 탄력성으로 변환하고(`탄력성 = 계수 × 물동량평균 / 통행량평균`, 또는 로그-로그 회귀), 신항선 관련 변수는 9.1의 재처리·버전 확정이 끝난 뒤 추가합니다. 북컨/남컨은 R²가 3~4%라 탄력성 산출 실익이 작아 요일 패턴 기반 정성적 시나리오로 대체하는 걸 제안합니다.

### 9.3 RQ2(현재 취약구간) 우선순위

1. **1순위**: 서컨-남해선 김해JC-동김해IC 구간 — 이번 재실행에서 가장 안정적으로 유의. 음의 방향성 원인 확인.
2. **1순위**: 서컨-신항선 축(대청IC-진해IC·남진례IC-대청IC·진해IC-남문대교 3구간 전체) — 다중공선성 재처리와 함께 공간적으로도 재검토(세 구간이 실제로 얼마나 붙어있는지).
3. **2순위**: 세산교차로 — 제1배후도로 병목 가설 검증.
4. 북컨/남컨 관련 구간은 후순위, 항만배후도로(부산항대교·을숙도대교) 파일럿 분석에 우선 배분.

### 9.4 RQ3·RQ4 반영 방향

RQ3의 시나리오 오버레이에는 9.2에서 확정될 탄력성(우선 남해선 김해JC-동김해IC)을 가정치로 적용하고, 신항선 관련 변수는 9.1이 끝난 뒤 추가합니다. RQ4에서는 병목 구간(신항선 축, 세산교차로)과 정책자료를 대조한 매칭표에 확정된 계수를 정량적 근거로 제시합니다.
